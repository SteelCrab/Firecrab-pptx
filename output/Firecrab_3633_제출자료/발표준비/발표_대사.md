## 2페이지 팀 소개

JustForFun의 박용현입니다. 프로젝트의 기획과 설계, 개발과 검증을 담당했습니다. AI 작업 환경과 서비스 운영을 함께 관리하는 데 초점을 맞췄습니다.

## 3페이지 프로젝트 개요

목표 25초 · 누적 00:55

Firecrab은 AI 작업부터 앱 배포와 운영까지 한곳에서 관리하는 오픈소스 플랫폼입니다.

Sandbox와 Canvas에서 AI 작업과 결과를 다루고, MicroVM과 Cluster에서 실행 환경을 관리합니다. Deploy로 앱을 배포한 뒤에는 로그와 상태를 확인합니다.

이 기능들을 사용자 서버와 클러스터에서 운영합니다. 이런 구성이 필요한 배경부터 보겠습니다.

## 4페이지 개발 배경과 목적

목표 35초 · 누적 01:30

AI로 코드를 만드는 것만으로 서비스 운영이 끝나지는 않습니다.

도구를 따로 사용하면 대화와 코드, 실행 결과가 흩어집니다. 작업 환경과 접근 권한도 직접 맞춰야 합니다. 배포한 뒤에는 로그와 서버 상태를 여러 도구에서 확인해야 합니다.

Firecrab의 목적은 AI 작업과 실행 환경, 배포·운영을 한곳에서 관리하는 것입니다. 이 구성을 다른 플랫폼과 비교해 보겠습니다.

## 5페이지 플랫폼 비교

목표 35초 · 누적 02:05

비교 기준은 주요 기능과 운영 위치입니다.

Replit, Modal, Vercel, Fly.io는 각 플랫폼이 관리하는 인프라에서 개발이나 실행, 배포 기능을 제공합니다. Coolify처럼 사용자 서버에서 운영하는 플랫폼도 있습니다.

Firecrab은 보유한 서버와 클러스터에서 AI 작업, MicroVM 격리, 앱 운영을 함께 관리하는 데 초점을 둡니다. 공개 코드를 수정해 운영 환경에 맞게 확장할 수도 있습니다.

이 기능들이 어떻게 구성되는지 보겠습니다.

## 6페이지 올인원 통합 구조

목표 30초 · 누적 02:35

Firecrab의 구조는 세 영역으로 나눌 수 있습니다.

AI 기능에는 작업을 실행하고 검토하는 Sandbox와 협업 공간인 Canvas가 있습니다. 실행 인프라에는 MicroVM과 여러 호스트를 관리하는 Cluster가 있습니다. 서비스 운영에는 배포와 업데이트, 상태 확인과 복구 기능이 있습니다.

작업 결과와 실행 환경, 배포 상태를 같은 콘솔에서 확인하고 관리합니다. AI Canvas도 이 안의 AI 기능 중 하나입니다.

먼저 AI Sandbox부터 보겠습니다.

## 7페이지 AI Sandbox

목표 50초 · 누적 03:25

AI Sandbox는 AI가 만든 결과를 실제 실행 결과와 함께 검토하는 기능입니다.

프로젝트와 모델을 선택하면 프로젝트 사본에서 작업을 시작합니다. 명령과 테스트는 선택한 MicroVM에서 실행합니다. MicroVM은 작업 환경을 분리하는 가벼운 가상머신입니다.

사용자는 어떤 파일이 바뀌었는지, 어떤 명령을 실행했는지, 테스트 결과가 무엇인지 확인할 수 있습니다. 검토한 뒤에는 선택한 파일을 원본 프로젝트에 반영합니다.

대화에서 받은 코드와 실행·검토 결과를 같은 작업 기록에서 확인하는 구성입니다.

이제 이런 작업을 여러 에이전트로 나누는 방식을 보겠습니다.

## 8페이지 멀티 AI 에이전트

목표 40초 · 누적 04:05

작업이 커지면 에이전트마다 역할을 나눌 필요가 있습니다.

예를 들어 로그인 기능을 만든다면, API를 구현하는 작업과 화면을 구현하는 작업을 나눌 수 있습니다. 선행 작업의 결과와 변경 파일은 다음 작업의 사본에 전달합니다.

사용자는 각 작업의 명령과 테스트, 산출물을 확인할 수 있습니다. 무엇을 실행했고 어떤 변경을 반영했는지도 기록으로 확인합니다.

현재 프로젝트 내 실행은 순서대로 진행하며, 재시도는 명시적으로 요청합니다.

이 작업들을 함께 살펴보는 공간이 AI Canvas입니다.

## 9페이지 AI Canvas

목표 40초 · 누적 04:45

AI Canvas는 사람과 AI 에이전트가 함께 쓰는 협업 AI 작업 공간입니다.

지금 보이는 화면은 테스트 데이터로 만든 UI 목업입니다.

왼쪽에는 프로젝트 자료와 작업 목록이 있습니다. 캔버스에는 역할별 에이전트와 터미널, 공유 파일과 문서가 배치되어 있습니다. 앱 미리보기와 변경 기록도 같은 공간에서 확인하는 구성입니다.

사용자가 대화와 파일, 실행 결과를 따로 찾아다니지 않고 작업 맥락을 함께 확인하도록 구성했습니다.

Canvas는 Firecrab의 AI 기능 중 하나입니다. 실제 코드 실행은 Sandbox의 격리 환경에서 다룹니다.

## 10페이지 AI 실행 보안

목표 50초 · 누적 05:35

AI가 만든 코드를 실행할 때는 어디서 실행하고 어디까지 접근할 수 있는지가 중요합니다.

Firecrab은 별도의 운영체제 커널을 가진 MicroVM에서 작업을 실행합니다. 전용 사용자와 네트워크 규칙으로 실행 권한과 연결 범위를 설정합니다.

모델 연결에 사용하는 자격증명은 API 호스트에서 관리하고, 작업용 가상머신과 모델에 전달하는 내용에서 분리합니다.

원본 코드 반영도 별도 단계입니다. 사용자가 변경 내용을 검토하고 적용할 파일을 선택합니다.

격리 실행과 결과 검토를 거쳐 서비스 배포로 이어지는 구성을 보겠습니다.

## 11페이지 서버리스 배포·운영

목표 50초 · 누적 06:25

앱 배포는 준비한 OCI 이미지를 기준으로 진행합니다. OCI 이미지는 앱과 실행에 필요한 파일을 묶은 표준 이미지입니다.

AI 작업 결과를 검토해 코드를 반영하고, 이미지를 준비한 뒤 Deploy에서 배포합니다. 코드 반영과 이미지 준비, 배포는 각각 확인하는 단계입니다.

배포할 때는 HTTP 준비 상태를 확인합니다. 이후에는 업데이트와 롤백을 관리합니다.

이미지 저장소나 DB 같은 외부 서비스의 연결 정보는 PIPE에서 관리합니다.

이렇게 앱을 배포한 뒤, 여러 호스트에 있는 VM과 서비스를 관리하는 기능이 Cluster입니다.

## 12페이지 클러스터 관리

목표 50초 · 누적 07:15

Firecrab은 여러 호스트를 클러스터로 구성할 수 있습니다.

먼저 호스트를 등록하고 보유 자원과 준비 상태를 확인합니다. 그다음 VM과 앱 복제본이 실행될 호스트를 관리합니다. 복제본은 같은 앱을 여러 개 실행하는 단위입니다.

그림에서는 두 호스트의 VM과 앱 복제본을 한곳에서 확인하는 구성을 보여 줍니다. 요청한 배포 기록과 실제 상태를 함께 확인할 수 있습니다.

현재 네트워크와 디스크는 호스트별 자원으로 관리합니다.

서버가 늘어났을 때도 같은 콘솔에서 배치와 상태를 확인하는 데 초점을 뒀습니다. 이제 준비한 작업 결과와 앱 이미지로 전체 과정을 시연하겠습니다.

## 13페이지 기능 시연

목표 90초 · 누적 08:45

(시연 전에 AI 작업 결과와 앱 이미지를 준비한다. 실제 화면을 확인한 뒤 다음 대사를 읽는다.)

### 00–20초 AI 작업 결과 검토

(AI Sandbox의 작업 결과를 연다.)

먼저 준비한 AI 작업 결과입니다. 변경 파일과 실행한 명령, 테스트 결과를 확인합니다. 이 내용을 검토하고 원본에 반영할 파일을 선택합니다.

### 20–40초 MicroVM 실행 환경 확인

(작업에 연결된 MicroVM의 상태와 콘솔을 보여 준다.)

다음은 이 작업에 연결된 MicroVM입니다. 실행 환경과 할당 자원, 콘솔을 확인할 수 있습니다.

### 40–70초 이미지 배포

(미리 준비한 이미지를 선택하고 Deploy 실행과 준비 상태를 확인한다.)

검토한 코드로 미리 준비한 이미지를 배포하겠습니다. 배포 요청 뒤에는 앱의 준비 상태와 실행 상태를 확인합니다.

### 70–90초 앱과 로그 확인

(앱에 접속하고 배포 상태·로그·이벤트를 보여 준다.)

마지막으로 앱에 접속하고 로그와 이벤트를 확인합니다. AI 작업 결과 검토부터 실행 환경 확인, 앱 배포와 운영 상태 확인까지의 구성입니다.

## 14페이지 활용 방안과 계획

목표 55초 · 누적 09:40

활용 방안은 개인 개발과 개발팀 운영으로 나눌 수 있습니다.

개인 서버에서는 AI 프로젝트를 검증하고 앱을 운영할 수 있습니다. 개발팀은 여러 호스트에 배치한 VM과 앱 복제본을 같은 콘솔에서 관리할 수 있습니다.

다음 개발에서는 복구와 재연결 상황의 검증을 확대하고, 설치와 업데이트 안내를 보완할 계획입니다.

Firecrab은 Apache-2.0 라이선스로 코드와 문서를 공개합니다. Issue와 PR로 문제를 제보하거나 개선에 참여할 수 있습니다. CI 검사 구성과 ARM64 KVM 실행 기록도 공개해 검증 범위를 확인할 수 있게 합니다.

## 부록 대사

본 발표 시간에는 포함하지 않는다. 관련 질문을 받았을 때 사용한다.

### 16페이지 지원 환경

Linux에서는 KVM을 사용합니다. macOS는 중첩 가상화를 지원하는 관리 VM 환경을 사용합니다. Windows는 Preview 범위로 두고 추가 실기 검증을 진행할 부분을 구분하고 있습니다.

현재 클러스터 기능은 호스트 등록과 VM 배치, 앱 복제본 관리입니다. 관리 서버 이중화나 자동 호스트 장애 대체, 호스트 사이의 VM 이동은 이 범위와 구분합니다.

### 17페이지 사용 오픈소스

Firecrab에 실제 사용하는 핵심 오픈소스입니다.

Firecracker로 MicroVM을 생성하고 실행합니다. Tokio와 Axum으로 비동기 작업과 HTTP API 요청을 처리합니다.

웹 콘솔은 React로 구성합니다. 터미널에는 Ghostty Web를 사용하고, TLS 암호화 통신에는 rustls를 사용합니다.
