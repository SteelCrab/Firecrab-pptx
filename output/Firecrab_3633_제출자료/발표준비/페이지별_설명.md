## 1페이지 · Firecrab · 10초

프로젝트명과 핵심 주제를 소개한다. 멀티 AI 에이전트 구축과 서버리스 배포·운영을 위한 플랫폼이라는 점을 짚는다.

## 2페이지 · 팀 소개 · 20초

팀명은 JustForFun이다. 박용현이 기획·설계·개발·검증을 담당한다. 기획은 문제 정의와 기능 범위, 설계는 MicroVM과 클러스터 구조, 개발은 Rust API와 React 웹 콘솔, 검증은 테스트와 시연 환경을 중심으로 설명한다.

아이콘은 기획의 노트, 설계의 자, 개발의 코드, 검증의 체크를 표시한다.

## 3페이지 · 프로젝트 개요 · 25초

AI 작업·실행 인프라·서비스 운영을 한곳에서 관리하는 플랫폼이라는 개요를 설명한다. AI 기능에는 Sandbox·멀티 에이전트·Canvas가 있다. 실행 인프라는 MicroVM과 Cluster다. 서비스 운영에는 Deploy·로그·외부 서비스 연결이 있다. 오른쪽 콘솔은 예시 데이터 화면이다.

## 4페이지 · 개발 배경과 목적 · 35초

개별 도구를 따로 운영할 때 생기는 세 가지 불편을 설명한다. 대화·코드·결과가 흩어지고, 실행 환경과 권한을 직접 구성하며, 배포와 상태 확인이 나뉜다. AI 작업·실행 환경·배포 운영을 한곳에서 관리하는 것이 개발 목적이다. 권한 설정과 배포 검토는 사용자가 관리한다.

## 5페이지 · 플랫폼 비교 · 35초

주요 기능과 기본 운영 위치를 비교한다. Firecrab은 보유 인프라에서 AI 작업·MicroVM 격리·앱 운영을 함께 관리하는 구성에 초점을 둔다. Coolify도 사용자 서버에서 운영한다. 개별 기능의 독점이나 수치 성능 순위로 설명하지 않는다.

## 6페이지 · 올인원 통합 구조 · 30초

AI 기능, 실행 인프라, 서비스 운영의 통합 구조를 설명한다. Canvas는 AI 기능 중 하나다. 하단 흐름도가 아니라 각 영역의 역할과 통합 범위를 짚는다.

## 7페이지 · AI Sandbox · 50초

프로젝트 사본에서 AI 작업을 시작한다. 선택한 MicroVM에서 명령과 테스트를 실행한다. 변경 파일과 산출물을 검토한 뒤 선택한 파일을 원본에 반영한다. 화면은 검증용 데이터이며 실제 외부 모델과 게스트 실행의 증거 범위를 구분한다.

## 8페이지 · 멀티 AI 에이전트 · 40초

역할별 작업과 결과 전달을 설명한다. 선행 작업의 결과와 변경 파일을 다음 작업에 전달한다. 명령·테스트·산출물 기록으로 실행과 반영을 확인한다. 프로젝트 내 실행은 순서대로 진행하고 재시도는 명시적으로 요청한다.

## 9페이지 · AI Canvas · 40초

AI Canvas는 사람과 AI 에이전트가 함께 사용하는 협업 AI 작업 공간이다. 프로젝트 자료, 에이전트와 터미널, 공유 파일과 문서, 앱 미리보기와 변경 기록을 짚는다. 사용자 제공 화면 전체를 유지한다. 인터랙션 목업·테스트 데이터 화면임을 밝힌다.

## 10페이지 · AI 실행 보안 · 50초

별도 게스트 커널, 전용 사용자, 네트워크 규칙으로 실행 범위를 나눈다. 알려진 AI 공급자 자격증명은 API 호스트에서 관리한다. 원본에는 검토한 파일을 선택해 반영한다. 모든 보안 위험을 없앤다는 보장으로 설명하지 않는다.

## 11페이지 · 서버리스 배포·운영 · 50초

준비한 OCI 이미지로 앱을 배포하고 HTTP 준비 상태, 업데이트와 롤백을 관리한다. PIPE는 이미지 저장소·DB·Storage·Secret·도메인 연결 기능으로 짧게 설명한다. 앱의 데이터는 외부 DB와 Storage에서 관리하고 자격증명의 로컬 보관 범위는 별도로 구분한다.

## 12페이지 · 클러스터 관리 · 50초

호스트 등록, 보유 자원과 준비 상태 확인, VM과 앱 복제본 배치를 설명한다. 현재 네트워크와 디스크는 호스트별 자원이다. 컨트롤러 HA, 자동 호스트 장애 대체와 VM 이동은 현재 범위와 구분한다.

## 13페이지 · 기능 시연 · 90초

시연은 90초다. AI 작업 결과 검토 20초, MicroVM 환경 확인 20초, 준비한 이미지 배포 30초, 앱 접속과 로그 확인 20초로 구성한다. 새 모델 응답과 이미지 빌드 시간을 기다리지 않도록 실제 결과와 이미지를 미리 준비한다. 시연 영상은 재촬영 대기 상태다.

## 14페이지 · 활용 방안과 계획 · 55초

활용 방안, 개발 계획, 공개 개발 순서로 설명한다. 개인 서버의 AI 프로젝트 검증과 개발팀의 앱 운영에 활용한다. 복구·재연결 검증과 설치·업데이트 안내를 보완한다. Apache-2.0 코드·문서와 Issue·PR 기여 경로를 소개한다. ARM64 KVM 기록은 일시정지·재개·API 재연결 확인 범위다.

## 15페이지 · 마무리 · 20초

AI 작업과 서비스 운영을 한곳에서 관리한다는 가치를 정리한다. 감사 인사로 본 발표를 마친 뒤 질문을 받는다. 질문에 따라 16~17페이지 부록을 사용한다.

## 16페이지 · 지원 환경 · 질의응답용

질의응답용 부록이다. Linux는 KVM이 필요하다. macOS는 중첩 가상화가 가능한 관리 VM 환경을 사용한다. Windows는 Preview이며 추가 실기 검증 범위를 구분한다. 클러스터는 호스트 등록·VM 배치·복제 서비스 관리 범위로 설명한다.

## 17페이지 · 사용 오픈소스 · 질의응답용

질의응답용 부록이다. Firecracker는 MicroVM을 실행한다. Tokio·Axum은 비동기 작업과 HTTP API를 처리한다. 웹 콘솔은 React, 터미널은 Ghostty Web이다. rustls는 TLS 암호화 통신을 처리한다. 발표자가 확인한 구성을 기준으로 설명한다.

## 자료 기준

웹 콘솔은 React, 터미널은 Ghostty Web으로 설명한다. AI Canvas는 사용자 제공 전체 화면을 사용한다. 비교표는 주요 사용 범위와 기본 운영 위치를 설명한다.
