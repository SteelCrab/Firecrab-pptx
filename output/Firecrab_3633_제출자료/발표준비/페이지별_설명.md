## 1페이지 · Firecrab · 10초

프로젝트명과 핵심 주제를 소개한다. 팀명 JustForFun, 접수번호 3633, 발표자 박용현을 표시한다.

## 2페이지 · 팀 소개 · 20초

팀명은 JustForFun이다. 박용현이 기획·설계·개발·검증을 담당한다. 기획은 문제 정의와 기능 범위, 설계는 MicroVM과 클러스터 구조, 개발은 Rust API와 React 웹 콘솔, 검증은 테스트와 시연 환경을 중심으로 설명한다.

## 3페이지 · 프로젝트 개요 · 25초

AI 작업·실행 인프라·서비스 운영에 각각 기존 IconPark 기능 아이콘을 추가한다. AI 기능은 Sandbox·멀티 에이전트·Canvas다. 실행 인프라는 MicroVM·Cluster다. 서비스 운영은 Deploy·로그·외부 서비스 연결이다. 콘솔은 예시 데이터 화면이다.

## 4페이지 · 개발 배경과 목적 · 45초

개발 순서를 네 단계로 설명한다. Firecracker 인프라 대시보드 구축, 필요한 내부 관리 기능 구현, 배포·운영 도구 지원, AI Sandbox와 AI Canvas 구축 순서다. 발표자가 제공한 실제 개발 배경을 따른다.

## 5페이지 · 플랫폼 비교 · 45초

편집 가능한 기존 플랫폼 비교표를 유지한다. 오른쪽에는 관리형 플랫폼 대비 보유 서버 직접 구축, 배포 도구 대비 AI 작업·검토와 MicroVM 결합, 단일 콘솔의 관리 범위를 명시한다. Coolify도 자체 서버에서 운영한다. 개별 기능의 독점이나 측정하지 않은 성능 우위를 주장하지 않는다.

## 6페이지 · 올인원 통합 구조 · 30초

AI 기능, 실행 인프라, 서비스 운영의 통합 구조를 설명한다. Canvas는 AI 기능 중 하나다. 하단 흐름도가 아니라 각 영역의 역할과 통합 범위를 짚는다.

## 7페이지 · AI Sandbox · 50초

프로젝트 사본에서 AI 작업을 시작한다. 선택한 MicroVM에서 명령과 테스트를 실행한다. 변경 파일과 산출물을 검토한 뒤 선택한 파일을 원본에 반영한다. 화면은 검증용 데이터이며 실제 외부 모델과 게스트 실행의 증거 범위를 구분한다.

## 8페이지 · 멀티 AI 에이전트 · 40초

역할별 작업과 결과 전달을 설명한다. 선행 작업의 결과와 변경 파일을 다음 작업에 전달한다. 명령·테스트·산출물 기록으로 실행과 반영을 확인한다. 프로젝트 내 실행은 순서대로 진행하고 재시도는 명시적으로 요청한다.

## 9페이지 · AI Canvas · 40초

AI Canvas는 사람과 AI 에이전트가 함께 사용하는 협업 AI 작업 공간이다. 프로젝트 자료, 에이전트와 터미널, 공유 파일과 문서, 앱 미리보기와 변경 기록을 짚는다. 사용자 제공 화면 전체를 유지한다. 인터랙션 목업·테스트 데이터 화면임을 밝힌다.

## 10페이지 · AI 실행 보안 · 50초

별도 게스트 커널, 전용 사용자, 네트워크 규칙으로 실행 범위를 나눈다. 알려진 AI 공급자 자격증명은 API 호스트에서 관리한다. 원본에는 검토한 파일을 선택해 반영한다. 모든 보안 위험을 없앤다는 보장으로 설명하지 않는다.

## 11페이지 · 서버리스 배포·운영 · 50초

준비한 OCI 이미지로 앱을 배포하고 HTTP 준비 상태, 업데이트와 롤백을 관리한다. PIPE는 이미지 저장소·DB·Storage·Secret·도메인 연결 기능으로 짧게 설명한다. 앱의 데이터는 외부 DB와 Storage에서 관리하고 자격증명의 로컬 보관 범위는 별도로 구분한다.

## 12페이지 · 기능 시연 · 90초

시연은 90초다. AI 작업 결과 검토 20초, MicroVM 환경 확인 20초, 준비한 이미지 배포 30초, 앱 접속과 로그 확인 20초로 구성한다. 새 모델 응답과 이미지 빌드 시간을 기다리지 않도록 실제 결과와 이미지를 미리 준비한다. 시연 영상은 재촬영 대기 상태다.

## 13페이지 · 활용 방안과 계획 · 80초

활용 대상을 자가 서버 사용자, 테스트 사용자, 간단한 웹앱 개발자로 구체화한다. 별도 관리형 플랫폼 요금을 줄이는 활용을 설명한다. 서버·전력·모델 API 비용은 별도다. 마일스톤은 AI Canvas, AI 보안, 외부 플랫폼 연동, 장기 오픈소스 기여자 확보다. 확정하지 않은 날짜나 완료 상태를 만들지 않는다. Apache-2.0 공개 개발과 Issue·PR 기여 경로를 유지한다.

핵심 가치와 개발 방향으로 발표를 마친다. 감사와 질문 문구는 이 페이지에서 삭제한다. 다음 페이지에 별도 Q&A를 표시한다.

## 16페이지 · 크로스 플랫폼 · 질의응답용

운영체제 아이콘과 편집 가능한 아키텍처로 표현한다. Linux 직접 실행, macOS의 Virtualization.framework 기반 Debian VM, Windows의 WSL2 기반 Debian을 공통 Linux 실행 계층에 연결한다. Linux KVM과 x86_64·ARM64, macOS의 중첩 가상화와 M5 검증 기록, Windows Preview와 물리 PC·ARM64 검증 범위를 표시한다.

## 17페이지 · 사용 오픈소스 · 질의응답용

기존 오픈소스 목록에 실제 AI 연동 의존성 reqwest와 Serde를 추가한다. reqwest는 HTTP 요청을 처리한다. Serde와 serde_json은 도구 호출과 모델 응답의 JSON을 처리한다. 사용하지 않는 AI 프레임워크나 외부 모델 API를 오픈소스 목록에 넣지 않는다. 웹 콘솔은 React, 터미널은 Ghostty Web이다.

## 자료 기준

웹 콘솔은 React, 터미널은 Ghostty Web이다. AI Canvas는 사용자 제공 전체 화면을 유지한다. AI API 연동 오픈소스는 reqwest와 Serde다. 모델 API 자체를 오픈소스로 표시하지 않는다. 마일스톤에는 확정하지 않은 날짜를 넣지 않는다.
